API Design

Cloud endpoints (Next.js API routes) + what q-print sends

🔒 Guarded Ingest Routes (API key required)
POST /api/shops/register
One-time · called by setup.py · no auth needed
Request body
shop_name: "string"
hostname: "string"
college_name: "string"
Response 201
shop_id: "uuid-v4"
api_key: "secret"
POST /api/analytics/sync
Header: Authorization: Bearer <api_key>
Sends all pending days in one call
Request body
shop_id: "uuid"
days: [
 {
  date: "2026-04-06",
  jobs_completed: 45,
  jobs_errored: 2,
  jobs_dropped: 1,
  files_printed: 120,
  pages_color: 320,
  pages_bw: 530,
  revenue: 2450.00,
  peak_hours: [0,2,8…]
 }
]
Response 200
synced: 3 // days pushed
dates: ["2026-04-04",…]
Upsert by shop_id+date — safe to retry
🌐 Public Read Routes (no auth — used by dashboard)
GET /api/analytics/summary
All-time totals for KPI cards
total_jobs, total_files
total_pages_color/bw
total_revenue, success_rate
GET /api/analytics/trends
?days=30 · daily job counts for line chart
[{date, jobs_completed,
 jobs_errored, revenue}]
GET /api/analytics/peak-hours
Aggregated 24-slot array across all shops
hours: [0,0,2,8,15,20,…]
// index = hour of day
GET /api/analytics/campuses
Per-college breakdown for comparison
[{college_name, shops_count,
 jobs_completed, revenue}]
🖥 q-print Sync Module (new: server/src/analytics_sync.py)
Called from main.py on startup
1. query sync_log WHERE status='pending'
2. aggregate analytics_events by date
3. POST /api/analytics/sync
4. on 200 → update sync_log to 'synced'
5. on failure → retry in background
Aggregation (per day, per shop)
COUNT(*) WHERE event_type='completed'
COUNT(*) WHERE event_type='errored'
COUNT(*) WHERE event_type='dropped'
SUM(files_count), SUM(pages_color)
SUM(pages_bw), SUM(revenue)
GROUP BY hour → peak_hours[24]
